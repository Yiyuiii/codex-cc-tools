## Notes

The current Codex MCP server process did not inherit `OPENAI_API_KEY_DEEPSEEK`, so `providerProfile=deepseek` through the already-started MCP server was blocked by missing provider credentials. The same package successfully called DeepSeek through the CLI in the local shell environment. Persistent DeepSeek MCP use requires starting Codex or the MCP server with `DEEPSEEK_API_KEY` or `OPENAI_API_KEY_DEEPSEEK` in its environment.
